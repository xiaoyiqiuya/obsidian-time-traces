# 时迹 · Time Traces — 插件开发思路

> 砂糖 2026-06-13 | v0.2.3

---

## 一、核心理念

### 脚步计时法（事后记录）

传统计时器「先开始→后结束」——需要你在做事之前记得按开始，做事之后记得按结束。摩擦发生在两头。

时迹采用**做完一件事后记录**：
- 点击项目 → 自动计算距上次记录的时间差 → 写入
- 脑中始终有一个「时间沙漏」在滴答
- 连续点击同一项目自动合并，不做碎片化记录
- 心理效果：无所事事时，能清晰感觉时间在流逝

### 柳比歇夫体系

记录 → 统计 → 反思 → 调整。不是番茄钟，不是强制锁机，而是**自我觉知驱动自律**。

## 二、为什么是 Obsidian 插件

| 方案 | 优势 | 劣势 |
|------|------|------|
| Flutter 独立 App | 完整控制、性能好 | 需上架、多端开发、$$ |
| Obsidian 插件 | 零成本、跨平台、已有用户 Vault | 受限于 Obsidian 生态 |

**决定因素**：小邱已经在用 Obsidian + remotely-save，插件直接嵌入现有工作流。Flutter App 留到以后。

## 三、架构决策

### 数据存储：设置与数据分离

```
设置 → Vault 本地 .obsidian/plugins/time-is-gold/data.json
       （Obsidian 原生 loadData/saveData，永远能找到）

数据 → Vault 内 {自定义文件夹}/time-is-gold.json
       （Obsidian adapter API 读写，remotely-save 自动同步）
```

**为什么不放在 .obsidian/ 里**：remotely-save 为安全不同步 .obsidian/。放在可见文件夹 = 自动跨设备同步。

### 跨平台：adapter API 替代 fs

桌面端可用 Node.js `fs`，但 iOS/iPad 版 Obsidian（Capacitor webview）没有 `fs`。

**解决**：Vault 内模式使用 Obsidian 的 `vault.adapter` API（全平台通用），`fs` 仅用于桌面端「系统目录」模式，且 lazy require 避免移动端崩溃。

### 底部 Tab 栏：消除快捷键依赖

最初三个独立视图各需命令打开。整合为一个面板 + 底部三 Tab（🐾计时 · 🌳项目 · 📊统计），手指点切换，iPad 友好。

### SVG 图表：不用 CSS 变量

SVG 内 `fill="var(--text-accent)"` 在 Obsidian 中不解析。改用 `getComputedStyle(document.body).getPropertyValue()` 取实际色值，`createElementNS` 建 SVG 元素确保命名空间。

## 四、未解决的问题

### 1. iPad 输入摩擦

即使插件在 iPad 能运行，打开 Obsidian → 等待加载 → 切侧边栏 → 点面板 → 记录，链路太长。

**候选方案**：
- 桌面端起 HTTP 接口（localhost:18790/record），iPad 快捷指令一键 POST
- 不经过 Obsidian，直接写数据文件（remotely-save 同步回去）

### 2. Agent 间通信

砂糖(Reasonix) ↔ 伊涅芙(OpenClaw) 通过飞书群，但机器人互相 @ 不触发事件。目前需要小邱手动在群里协调。

### 3. 统计粒度

目前只有本周/本月。缺：自定义日期范围、同比环比、导出 CSV 报表。

## 六、技术栈

```
Obsidian Plugin API
├── 数据: vault.adapter (全平台) + fs (桌面)
├── 图表: document.createElementNS + SVG
├── 存储: 设置(super.saveData) / 数据(adapter.write)
└── 分发: GitHub + BRAT → iPad
```
